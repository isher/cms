一、系统概览

QScms 是一套以文件为存储介质的轻量级 CMS：前台动态渲染，同时内置静态站生成器，可以把整站导出为纯 HTML 交给 Nginx、对象存储或静态托管。文章、页面、菜单、站点参数、用户与权限全部存为 PHP 文件，不依赖数据库。

  • 动态前台：单一入口做路由分发，再套主题渲染。
  • 后台管理：文章、页面、广告、友链、留言、投票、插件、主题、语言包、备份、静态化各有独立功能页。
  • 文件存储：文章与页面为「索引数组 + 单行序列化正文」两层结构，配置类数据集中放在配置目录。
  • 多语言：后台与前台各有一套语言包，可在线编辑。
  • 内置能力：静态化 SSG、RSS 与站点地图、IndexNow、搜索引擎提交、投票、打赏、留言、图床、远程备份。

二、目录结构

├─ index.php        前台唯一入口（路由分发）
├─ register.php     前台用户注册
├─ control/         核心层：引导、函数库、登录鉴权与各功能库
│  └─ data/         配置、用户、权限、菜单、日志（运行时私有）
├─ data/            内容数据：文章、页面、广告
├─ files/           主题、静态主题、插件、语言包、图片、邮件模板
├─ admin/           后台目录（默认名，可任意改名）
├─ install/         安装向导 + 预设 + 安装锁
├─ static_site/     SSG 静态站输出
├─ upload/          本地上传（按月分目录）
└─ backups/         备份与快照

哪些能删：静态输出、后台临时文件与日志、备份目录都可清空后重建；安装完成后整个 install 目录可删除或改名。

哪些不能删：核心层、内容数据目录、主题与语言包、前台入口文件、后台目录。

三、安装与部署

环境要求、向导四步、装完必做事项与伪静态配置，都在 快速开始 里逐条写清楚了，这里不重复。只补三条经验：

  • 建议在 Web 服务器上禁止外网访问配置目录与备份目录，备份包不要落在站点根内。
  • 目录权限只放少数必需目录，代码目录保持只读；Linux 用 755/644，属主是 Web 运行用户（常见 www-data）。
  • Windows 部署同样可行：XAMPP / Apache 配虚拟主机即可，权限按 NTFS 账户给。

五、数据存储

  • 文章 / 页面两层：一层是列表索引（PHP 数组），一层是正文（PHP 注释头 + 序列化数据）。改内容格式时两层都要动。
  • 配置与权限：主配置、权限、菜单、静态化参数、插件开关都是独立 PHP 文件，直接可读可备份。
  • 账号口令：密码用 Argon2ID 哈希，不可用时回退默认哈希。
  • 迁移：整站目录拷走即是完整备份，换机器不用导库。

六、主题、插件与多语言

  • 主题在主题目录下，一个目录一套；后台「基本参数」切换，主题自带选项面板，「主题代码编辑器」可在线改模板。
  • 插件分系统插件与用户插件两类，后台插件管理页启停并维护黑名单。
  • 语言包后台一套、前台一套，后台语言包编辑器可就地改键值，新增语种要补齐全部键，缺的会回退英文。
  • 主题效果与适用场景见 主题模板。

七、静态化（SSG）

  • 后台「静态化」配置输出路径、站点地址与生成选项；静态菜单与动态站菜单相互独立。
  • 生成引擎按静态主题渲染页面与文章，写出输出树；生成后可推送到 Cloudflare Pages / FTP / SFTP，或同步到 GitHub Pages。
  • 支持增量与全量两种模式；静态站缺页或为空时，先核对静态主题是否存在、输出路径是否正确，再删缓存全量重生成。
  • 源站可以只用来编辑，公网只对外暴露静态 HTML，安全面最小。

八、AI 发文接口

留给外部 Agent（大模型、自动化工具）写入文章的入口，写入口径与后台编辑器一致。

  • 鉴权：请求头带密钥，配置里只存密钥的 sha256 哈希，比对用恒定时间算法。
  • 开关：接口默认关闭，未开启或密钥为空时直接返回 403。
  • 字段：标题、正文、摘要、标签、状态（发布或草稿）、日期时间、文章 id、作者、是否允许评论；支持新建与按 id 覆盖。
  • 边界：只认 API Key、不校验后台登录态；不能删除文章、不能改配置或密码、不能上传文件、无命令执行；文章 id 已过滤路径字符，不能穿越写任意文件。
  • 建议：密钥用密码学随机生成，不要写进前端、日志或 URL；公网开放时叠加 IP 白名单或限流。

九、安全加固

风险点做法
后台路径被扫装完第一件事换 6～10 位无规律目录名，访问一次新目录即自动记录
目录列表暴露关闭 Options Indexes
配置与备份被下载Web 服务器禁止访问配置与备份目录，备份包不要放站点根内
安装入口长期暴露装完删除或改名 install 目录
口令明文传输后台登录走 HTTPS
站内工具被滥用可执行命令的页面仅对超级管理员开放，生产环境按需停用

后台目录为什么能随便改：程序在运行期从请求路径第一段取目录名，并校验后台母版文件存在，结果记进配置。所以改目录不用改代码、不用改配置。

十、日常操作

  • 发文章：文章 → 新建 → 标题 / 标签 / 日期 → 编辑器写正文 → 发布或存草稿。
  • 建页面：页面 → 新建 → 设定路径（如 about）→ 访问站点带路径即可。
  • 改菜单：动态站与静态化各一套菜单，互不影响。
  • 换主题 / 调样式：基本参数选主题；在线改模板用主题代码编辑器。
  • 上传与图床：默认按月存本地；图床页选驱动并测试，开启后正文图片可自动改写。
  • 朗读：文章页按开关与提供商朗读，默认浏览器原生语音合成，可换其他 TTS。
  • 投票 / 打赏 / 留言：投票插标签渲染，判重按 cookie + IP + 账号；打赏填收款信息，前台展示。
  • 静态化：配置 → 保存 → 生成 → 检查输出目录的首页文件。
  • 备份：后台手动打包下载，或计划任务定时打包并 FTP 上传、邮件通知。
  • 多站点：为每个域名配主题与语言，静态化按站点分别输出。
  • 屏蔽词：维护词库，保存内容时提示命中。

500 / 白屏主配置损坏或不可读；开 display_errors 看具体报错
登录后又回登录页会话令牌与来源绑定，IP 变化或 Cookie 被清；重新登录
提示无权限检查用户组权限、个人追加 / 禁用项、页面权限守卫映射
