QsisCMS 实战搭建｜一套文件式静态生成 CMS，打造你的独立自媒体站点

2026-08-28 · 乔硕

如果你厌倦了 MySQL 数据库频繁维护、WordPress 臃肿卡顿，又想要可以自主可控、一键生成静态站点、推送到 GitHub‑Pages 托管的建站方案，QsisCMS会是一个非常有特色的轻量选择。本文基于后台实操界面，完整分享落地实战经验。

一、什么是 QsisCMS

QsisCMS 是一款基于 PHP 开发、以文件存储为核心的内容管理系统。 它不走传统数据库路线，文章、配置全部落地成 Markdown / 文本文件，内置 SSG（静态站点生成器）引擎。写完文章之后，一键渲染生成纯 HTML 静态网页，再同步部署到 GitHub Pages、云服务器。

核心优势

无数据库依赖，不需要安装 MySQL、SQLite，迁移站点只需要复制网站文件夹。

SSG 静态生成，对外访问全部是静态页面，速度快、几乎不会被 SQL 注入攻击。

内置 GitHub‑Pages 一键同步，写完文章直接推送至仓库，自动上线。

后台可视化管理，自带文章编辑、分类标签、站点地图、RSS 订阅、IndexNow 搜索引擎推送全套 SEO 工具。

高度可定制：自定义主色调、隐私协议、404 页面、favicon 图标、多语言配置。

二、后台功能分区实战解读

从截图的后台控制面板，我们可以把系统划分为五大模块。

1. 基础参数（站点全局配置）

这是网站的根配置面板。

站点状态：open/close开关，一键关闭网站，开启维护模式。

标题、标题描述、关键词、站点描述：直接对应网站首页 SEO 元标签。也就是公众号 “深悟笔记” 的口号：观世事入木三分，悟本质点到即止，就填写在此处。

网站地址、虚拟目录：配置你的访问域名，例如 https://c.qsis.cn:88。

qc_post_dir、qc_page_dir：指定文章与单页内容存放的文件夹路径。

标志上传：上传网站 favicon、站点 logo 图标。

实战建议：网站域名一旦确定，后期尽量不要改动，否则 SSG 生成的静态链接、sitemap 站点地图会出现大量 404 错误。

2. 账户相关（管理员权限）

这里管理超级管理员账号身份：

控制台账号：后台登录账号。

Display_Account：前台对外展示的作者名称。

verify_email：用于接收系统通知、找回密码的邮箱。

启用用户模式：开启之后，可以拆分管理员、普通撰稿人权限，多人协作维护站点。

注意：修改昵称之后系统强制要求重置管理员密码，这是后台内置的安全机制。

3. 核心业务模块

文章：Markdown 编辑器撰写内容，支持设置分类、标签、发布时间，对应你公众号五个栏目：认知心理、格物思理、人生成长、人文笔记、实操方略。

网页：生成独立单页。例如关于我们、联系方式、隐私政策页面。

Static‑Site(SSG)：最核心的静态生成面板。点击生成，系统遍历所有 md 源文件，渲染输出完整的静态 HTML 站点。

GitHub_Pages_Sync：配置 Token、仓库地址，一键将生成好的静态文件强制推送到 GitHub 仓库，实现全自动上线。

PostAPI 接口配置 & 远程文章源同步：跨站点文章推送工具，可以实现两套 QsisCMS 站点之间文章一键同步，搭建内容矩阵。

4. 配套运维工具

插件：扩展附加功能。

系统备份：一键打包全站文件备份。

log_operate：完整操作审计日志，记录后台每一次修改、API 调用行为，方便排查误操作。

查看留言：开启留言功能后的访客消息管理。

三、完整建站实战流程

步骤 1. 基础配置初始化

填入站点标题、SEO 描述、关键词。

填写正式域名，设置好文章目录路径。

上传站点 Logo 图标。

保存基础设置。

步骤 2. 管理员账户配置

设置登录账号密码。

填写对外展示作者名与联系邮箱。

如果需要多人写作，开启「启用用户模式」。

步骤 3. 撰写内容

后台‑文章板块新建文章。 写完文章后先保存源文件，不要立刻发布。你可以先在本地预览，调整排版，规避公众号类文章查重风险、打磨口语化朗读文稿。

步骤 4. SSG 静态生成

进入 Static‑Site (SSG)面板，执行全站构建。 系统一次性生成：

所有文章、分页页面

分类页、标签页

RSS 订阅源

search‑index 搜索索引

sitemap.xml 站点地图

robots.txt、IndexNow 验证文件

404 错误页

步骤 5. GitHub Pages 同步上线

切换至 GitHub‑Pages‑Sync 标签页，填入你的仓库地址、GitHub Token。 点击推送，生成出来的静态站点直接上传，几分钟后 GitHub Pages 即可对外访问。

步骤 6. 搜索引擎主动推送

生成站点地图后，系统自带 IndexNow 推送功能，主动把新文章提交给搜索引擎，缩短收录等待时间。

四、实战踩坑经验总结

文件修改时间坑点：最初 SSG 生成页面会读取文件修改时间作为文章发布时间。后期需要手动修改代码，改为读取文章头部元数据里的发布时间，否则每次重新生成站点，所有文章时间全部错乱。

Git 推送 408 超时报错：推送 GitHub 失败，优先检查 Token 权限是否开启 repo 完整权限、本地网络能否连通 GitHub。可调整 PHP 脚本超时时间、添加重试逻辑。

跨域名 canonical 标签：如果你本地预览域名和线上 GitHub 域名不一致，生成静态页面时需要开启规范链接标签，避免搜索引擎判定重复内容。

无数据库备份：因为所有文章都是 Markdown 源文件，备份站点直接下载整个 files 文件夹，文章素材就全部保存。

五、适合什么样的人群

✅ 自媒体博主，运营公众号、独立博客，追求网站长期可控，不想被平台规则约束。

✅ PHP 开发者，喜欢二次开发，自定义后台功能。

✅ 需要做多账号内容矩阵，利用 PostAPI 跨站同步文章。

✅ 预算有限，希望免费托管站点，使用 GitHub Pages 上线。
